# 反思框架

> 反思触发条件、四步法流程和质量检查

---

## 反思触发条件

### 自动触发（满足任意一条）

1. **累计 5-8 条新记忆**：碎片记忆积累到一定量，需要整理
2. **完成一个功能模块**：阶段性总结的好时机
3. **出现重大 bug / 走了弯路**：需要记录教训
4. **项目里程碑节点**：需要更新全局架构

### 手动触发

- 用户明确要求："反思一下"、"总结一下"、"复盘一下"
- Agent 自己判断需要复盘

### 执行命令

```bash
mw reflect "模式描述" "纠正总结"
```

## 反思四步法

### 第一步：回顾（Review）

**把这段时间的所有记忆过一遍，回答：**

1. 做了什么？（完成了哪些工作）
2. 遇到了什么问题？
3. 怎么解决的？
4. 哪些做得好？哪些做得不好？

**做法**：
```bash
# 查看最近的记忆
mw search "最近" --extra 进展 完成 修复

# 查看统计
mw stats
```

**输出**：整体回顾摘要

---

### 第二步：提炼（Extract）

**从回顾中提炼可复用的通用经验，回答：**

1. 哪些经验是通用的，以后还会用到？
2. 哪些做法可以固化为规则/最佳实践？
3. 哪些坑是典型的，需要专门标记为反模式？
4. 哪些决策逻辑可以沉淀下来？

**做法**：
```bash
# 把提炼出的经验写入
mw ingest "## 经验：{经验名称}
- **场景**：...
- **发现**：...
- **原因**：...
- **可复用性**：..." --label "经验" --scope project --summary "..."

# 把反模式写入
mw ingest "## 反模式：{错误做法}
- **错误做法**：...
- **正确做法**：...
- **原因**：..." --label "经验" --scope project --summary "..."
```

**输出**：
- 新增的规则/经验/bug-fix 记忆，反模式通过 meta status 标注
- 需要更新到全局记忆分类的内容清单

---

### 第三步：整理（Organize）

**对现有记忆库做整理，回答：**

1. 有没有重复的记忆？需要合并
2. 有没有被新方案替代的旧记忆？需要标记 deprecated（meta JSON 约定）
3. 有没有过期的记忆？`mw cleanup --stale`
4. 有没有 scope/category 打错的？`mw update <doc_id> --scope/--category` 修正
5. 有没有 draft 状态的（meta 约定）可以升级为 confirmed？

**做法**：
```bash
# 搜索可能重复的记忆
mw search "关键词"

# 更新记忆状态（通过 meta JSON）
# 合并重复记忆：mw ingest 新版本 + mw update 旧版本

# 搜索可能过期的记忆
mw search "旧方案" --extra v0.1 v0.2
```

**输出**：
- 合并/删除/标记的记忆清单
- 标签/scope 修正清单
- meta status 变更清单

---

### 第四步：展望（Look Ahead）

**面向未来，回答：**

1. 还有哪些知识缺口需要补充？
2. 接下来的优先级是什么？
3. 有什么风险需要提前注意？
4. 有没有什么方向值得提前探索？

**做法**：
```bash
# 记录待办
mw ingest "## 待办：{任务}
- **优先级**：high/medium/low
- **依赖**：...
- **状态**：pending" --label "项目记录" --scope project --summary "..."
```

**输出**：
- 更新后的 todo 列表（按优先级排序）
- 风险提示
- 下一步建议

## 反思执行 Prompt

**你是项目复盘专家。请对给定时间段的记忆进行深度反思复盘。**

### 输入

- 这段时间的所有记忆
- 当前项目状态

### 输出格式

```
反思复盘报告

一、整体回顾
（这段时间做了什么，整体进展如何）

二、关键经验提炼
✅ 最佳实践（可复用的好做法）
1. ...

⚠️ 踩坑记录（以后要避免的）
1. ...

📌 重要决策
1. 决策内容 + 原因 + 结果

三、记忆库整理
合并重复
- [记忆A] + [记忆B] → 合并为 [新记忆]

标记废弃
- [记忆X] → deprecated，因为（meta JSON 约定）
   替代方案：[记忆Y]

draft 升级
- [记忆Z]：draft → confirmed（meta JSON 约定）

四、后续计划
高优先级待办
1. ...

中优先级待办
1. ...

风险提示
1. ...

五、反思结论
（一句话总结这次反思的核心收获）
```

## 反思后的动作

反思报告生成后，必须执行以下操作：

1. **写入新记忆**：把提炼出的最佳实践、踩坑记录作为新的记忆写入
2. **修正标签/scope**：`mw update <doc_id> --label/--scope/--category`
3. **重建关联**：`mw crawl`（新记忆之间的实体关联）
4. **进化系统**：`mw evolve`（让系统自动调整权重和层级）
5. **记录反思**：把这次反思本身作为一条记忆存下

```bash
mw ingest "## 反思：{主题}
- **时间**：...
- **核心发现**：...
- **关键决策**：..." --label "经验" --scope project --summary "..."
```

## 质量检查清单

反思不是走过场，检查以下几点确保质量：

- [ ] 有没有提炼出至少 3 条可复用的通用经验？
- [ ] 有没有识别出至少 2 个踩坑/反模式？
- [ ] 有没有对记忆库做实际的整理（合并/标记/修正）？
- [ ] 有没有明确的后续计划和优先级？
- [ ] 反思结论是不是具体的、可执行的，而不是空话？

**如果以上有超过 2 条没做到，说明反思不够深入，重新来。**

---

## 反思频率建议

| 场景 | 频率 |
|------|------|
| 日常开发 | 每完成一个小功能 |
| 项目开发 | 每个 sprint / 每周 |
| 踩坑后 | 立即反思 |
| 里程碑 | 必须反思 |
| 用户要求 | 随时 |
