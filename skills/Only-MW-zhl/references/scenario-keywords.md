# 场景→关联词映射

> 搜索时使用 `--extra` 添加关联词，用 OR 语义扩大覆盖。

## 何时使用 --extra

| 场景 | 用 --extra | 原因 |
|------|:-:|------|
| 关键词太窄，搜不到 | ✅ | 扩大覆盖，提高召回 |
| 关键词太泛，结果太多 | ❌ | 应该用更精确的主关键词缩小 |
| 用户说"全面了解"/"所有相关" | ❌ | 用 `--graph` 代替 |
| 闲聊/确认 | ❌ | 不需要 |

## 何时使用 --graph

| 场景 | 用 --graph | 原因 |
|------|:-:|------|
| 单一关键词搜索 | ❌ | 默认融合够了 |
| 用户说"全面了解"/"所有相关" | ✅ | 图谱展开 |
| 搜索结果少于 3 条 | ✅ | 尝试关联扩展 |
| 闲聊/确认 | ❌ | 不需要 |

## 场景→关联词

| 场景 | 主关键词 | 可用的 extra 关键词 |
|------|---------|-------------------|
| 部署 | 部署 | 打包、发布、CI、CD、上线、Vercel |
| 调试 | 调试 | 报错、错误、排查、日志、异常 |
| 架构 | 架构 | 设计、选型、方案、重构、模块 |
| 数据库 | 数据库 | 迁移、schema、索引、查询 |
| 配置 | 配置 | 环境变量、.env、settings、参数 |
| 编码 | 编码 | 写代码、命名、注释、规范、函数、类 |

## 生成关联词的原则

1. **优先从同义词表提取**：SDK 内置 `memory_synonyms` 表（如"bug"→"修复 错误 排错"）
2. **参考已有记忆的 keywords 字段**：命中记录的 keywords 中可能有相关词
3. **不要盲目堆砌**：3-5 个关联词足够，过多会降低搜索精度
4. **场景驱动**：根据用户当前任务上下文判断关联词

# 搜索结果评估

> RRF 分是**相对排序分**，不是绝对质量分。同一查询 top-1 可能只有 0.2。用 `--explain` 查看各路分数确认匹配质量。

| 分数范围 | 含义 | 做法 |
|---------|------|------|
| score > 0.5 | 强匹配 | 直接引用 |
| 0.3 ≤ score ≤ 0.5 | 部分匹配 | 引用但注明相关性 |
| score < 0.3 | 弱匹配 | 不应直接引用，换关键词再搜 |

## Dedup 注意事项

C++ 搜索引擎有 5 分钟去重窗口（`dedup_window_minutes`）：同一段 summary 文本在窗口内不会重复返回。
正常使用不会触发（不同结果有不同摘要），但如果连续搜索同一关键词且结果集不变，可能导致返回数减少。
不影响 `mw crawl` / `mw graph-traverse` 等其他操作。
